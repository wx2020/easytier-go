# Clean-Room Compatibility Policy (FND-03)

> **Status: Active — governs the Go rewrite (`go/`) until VAL-05 cutover.**
> See also `docs/GO_REWRITE_SE.md` §1, §8.2.1 and §11.

## 1. Purpose

The Go implementation is a **clean-room behavioral reimplementation** of EasyTier 2.6.4
(`official-release` / `8428a89d`, Rust 1.95). Rust source is the **compatibility
oracle and specification**, not a codebase to copy. This document defines how the
Rust source may be used without creating a derivative work that would violate the
LGPL-3.0 intent or contaminate licensing, and how compliance is verified.

## 2. Governing principle

*Go code must not be a line-for-line translation of Rust source. It must be
written from behavioral contracts (wire formats, config schemas, RPC descriptors,
and test vectors).*

Allowed: observing Rust behavior via running binaries, captured packets,
TOML fixtures, protobuf field numbers, and deterministic test vectors emitted by
the oracle fixture generator under `go/testdata/compat/`.

Not allowed: copying Rust source text, comments, or non-trivial control-flow
structures into Go files; pasting Rust struct definitions and renaming fields;
translating Rust macros/functions mechanically.

## 3. What is the oracle and what may be reused

| Artifact | Origin | How Go may use it | License handling |
|---|---|---|---|
| Wire-format fixtures (`go/testdata/compat/packet`, `handshake`, `noise`, `secure`, `wg`, `route`) | Generated by Rust 1.95 oracle (`tools/gen-fixtures` and `go/cmd/gen-fixtures` equivalence check, §7.3 of `GO_REWRITE_TODOLIST.md`) | Consumed as **black-box byte vectors** in `TestGolden` — assertions compare Go codec output to committed bytes | Vectors are facts; commitment is byte-for-byte equality, not Rust code reuse. Files carry `LGPL-3.0-only`. |
| Protobuf `.proto` sources (`easytier/src/proto/*.proto`) | Rust workspace | **Reused verbatim**: `.proto` definitions are interface specifications. Go regenerates bindings via `protoc 3.21.12` + `protoc-gen-go 1.36.12` with field numbers locked (§4.1, API-01). Generated `*.pb.go` is covered by `LGPL-3.0-only`; generator output notice is preserved. | `LGPL-3.0-only` |
| Configuration fixtures (`go/testdata/compat/config`) | Rust oracle + reference TOML | Parsed as input/output pairs for `internal/config` normalization tests | `LGPL-3.0-only` |
| Documentation and help text | `easytier/src/easytier-core.rs` help strings | Behaviorally reproduced; help-table/JSON contracts are tested via CLI golden tests (`cmd/easytier-core`, `cmd/easytier-cli`) | No source copied; behavior cloned |
| Third-party dependencies (e.g., `x/crypto`, `noise`, `websocket`, `klauspost/compress`) | Upstream Go modules | Used via `go.mod`; each retains its own license (MIT/BSD/Apache-2.0) | Tracked in SBOM; see §4 |

Mechanical translation is prohibited. | LGPL-3.0; no derivation via copy |

## 4. License and SPDX hygiene

- **Primary license:** `LICENSE` at repo root is `LGPL-3.0-only`. A REUSE-compliant copy lives at `LICENSES/LGPL-3.0-only.txt`.
- **SPDX identifiers:** Every Go source file carries a header:

  ```go
  // SPDX-FileCopyrightText: 2025 EasyTier Contributors
  // SPDX-License-Identifier: LGPL-3.0-only
  ```

  Build tags (`//go:build ...`) and `// Code generated by protoc-gen-go` notices
  remain at file top; SPDX follows them. `REUSE.toml` annotates generated files
  and vendored corpora.
- **Generated protobuf code** (`go/internal/proto/**/*.pb.go`): keeps the `Code generated by protoc-gen-go. DO NOT EDIT.` notice; SPDX is added beneath it. Field numbers are verified by `TestDescriptorFieldNumbers` (API-01).
- **Dependency licenses:** Go module licenses are enumerated in `go/go.mod` and in the SBOM emitted by the release workflow (`sbom.spdx.json` via `syft`). `go list -m -json all` is the source of truth; incompatibilities (e.g., GPL without linking exception) block a release. `govulncheck` and `syft` run in CI per `VAL-03` and `FND-05`.
- **REUSE compliance:** `reuse lint` (fsfe/reuse) is expected to pass: every file is either SPDX-tagged or covered by `REUSE.toml`. CI may invoke `reuse lint` in `go.yml`.

## 5. Clean-room workflow for contributors

1. **Read the spec first:** `docs/GO_REWRITE_SE.md` §4–§6 and the target ToDo row in `docs/GO_REWRITE_TODOLIST.md`.
2. **Consult fixtures, not Rust lines:** run `go test -run TestGolden` and inspect `go/testdata/compat/*`. If behavior is ambiguous, add a Rust fixture (via `tools/gen-fixtures`) and commit the vector with a migration record (§11), rather than copying Rust logic.
3. **Write Go idiomatically:** use Go error wrapping, `context.Context`, and narrow interfaces (`internal/peer` never imports OS-specific code). Do not transliterate Rust `Result`/`Arc`/`tokio` patterns.
4. **Prove compliance:** PR must reference ToDo ID(s), include unit + golden-vector tests, and pass `go vet`, `go test -race`, and fixture corpus diff (see `interop.yml` `fixture-corpus`). Any intentional divergence needs a `GO_REWRITE_SE.md` §11 design record.
5. **Review gate:** reviewers check for non-trivial Rust text overlap (`git diff --stat` plus spot search) and for missing SPDX/REUSE annotations.

## 6. Ownership and contribution licensing

All Go contributions are licensed `LGPL-3.0-only` (same as the Rust workspace) under
`SPDX-FileCopyrightText: 2025 EasyTier Contributors` unless a file explicitly states otherwise.
Third-party assets under `assets/`, `script/`, and `easytier-gui/` retain their existing licenses; they are not re-licensed by the Go rewrite. Contributors certify via Developer Certificate of Origin (DCO) on commit sign-off.

## 7. Auditing

- `go vet`, `go test -race`, and `reuse lint` run on every PR (`go.yml`).
- `interop.yml` ensures Go/Rust byte parity per `GO_REWRITE_SE.md` §8.4 and fails on unapproved fixture drift.
- SBOM + provenance generated per release (`go-release.yml`, FND-05) attests that shipped artifacts contain only declared licenses.

## 8. When the policy ends

This policy remains in force until `VAL-05` cutover. After the Rust core is removed from shipped products, the Go codebase remains `LGPL-3.0-only`; the clean-room constraint is then superseded by normal contribution licensing, but the SPDX/SBOM requirements persist.
